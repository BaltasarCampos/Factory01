# Contract: hooks

Registered in `.claude/settings.json` (guardrail file); each runs `factory hook <event>` and
reads the Claude Code hook JSON on stdin. Exit 2 = block (reason on stderr); exit 0 = allow.
Any internal error → exit 2 (fail closed): that blocks the action at PreToolUse (the gate and each guard), PreCompact and the first stop; at SessionStart Claude Code only reports it, and the gate then refuses every tool call, `passed.json` being absent, as the SessionStart row says; post-edit and log run after the tool, at PostToolUse, so their exit 2 reports the error to the session and undoes nothing, and the second stop is never blocked. A hook Claude Code stops at its timeout blocks only where it has `onFailure: "block"`: a timed-out post-edit, log or stop hook is expected not to block, so the Stop hook ends by its own deadline first (not yet probed: T125's S6 recorded only the `onFailure: "block"` case; T061's (86) probes it).

| `SessionStart` | `factory hook session-start` | What needs no git, against the session's record under `~/.factory/sessions/<session_id>/`, which the launcher writes: `FACTORY_ROLE` is its role, `FACTORY_ITEM` its item (unset for none), `FACTORY_STATION` its station, the input's `agent_type` its role, its `permission_mode` `dontAsk` or missing (Claude Code 2.1.322's SessionStart input carries none; the launcher's init check and the gate hold the mode, Owner decision 2026-11-11), and the hook input's `cwd`, by its real path, the record's clone. Passed → the session's log, `events.jsonl`, created empty if missing (append, 0600; one that cannot be created blocks, slice D-1b), then `passed.json` beside the record, written to a temporary file in the same folder and renamed into place, which every `PreToolUse` guard requires; failed, or a missing or malformed record → `passed.json` removed, a `blocked` event in the session's log, exit 2 (the session goes on, every tool call refused). Runs again after a compaction or a resume. | `Stop` | `factory hook stop` | The record's station's output at the session's head exists and passes its completeness check, Intake's against the record's repository and item; else block stop and log it in the session's log. No factory git runs in the session's clone: git reads it only inside the factory's bubblewrap sandbox, the clone read-only and nothing writable, and sends a full pack of what the session added since the record's head on its stdout, capped at 64 MiB; the factory indexes it with `index-pack --strict` in a quarantine under the session's own folder, checks there that the head is a commit of the pack, asked of the quarantine alone with no alternate (`cat-file --batch-check`, slice D-1a), whose history back to the record's head is whole, and only then moves the pack into the record's `project`, the factory's own clone, and keeps the commit under `refs/factory/sessions/<id>`, where the checks read it. Each git call is bounded at 120 s, and every program one stop starts, git in the sandbox or the factory's clone, `gh` and bubblewrap's probe, takes its timeout from one deadline, `STOP_DEADLINE`, 540 s, under the hook's 600 s timeout: the time left, read once, never 0, and with none left the program is not started; past it the stop fails as the factory's own error, logged as a `blocked` event at the first stop and an `alert` at the second (slices 28-5c-1, 28-5c-2); a program whose timeout was the time left and that timed out always ends with that refusal, decided once by `bound()` for every caller, never by a second reading of the clock, and one stopped by its own shorter cap keeps its own message (slice 28-5c-4b). A test replaces `node:child_process`'s spawn functions and fails on any program started without a positive timeout while a stop runs, over the stops of every station in its rows (Spec, Plan, Build, Test, the Reviewer, Security, Define and Intake), and a slow `gh` is stopped at the deadline: it proves those rows' paths, not every path a stop could take. The session ref and the passing head are written with git's compare-and-swap, `update-ref <ref> <new> <old>`, so a second Stop hook racing the first fails instead of overwriting it, with no lock file (slice 28-5c-2). A head that fails those checks blocks the stop with the reason; a failure of the factory's clone or of bubblewrap fails the hook (slice 28-5a). For Spec, the Planner, Test, the Reviewer and Security, which commit nothing, the clone's HEAD must still be the record's head, and the hook commits their output itself: only their write column's paths, read by node inside the same read-only sandbox, each a regular file with no link at it or above it, at most 8 MiB in all, never a protected path, a path `deny_write` or a relative `deny_read` pattern denies (lower-cased, as the path guard matches), a part git refuses (`.git` in any case) or a name ending in a dot; committed in the factory's clone with a temporary index on the record's head, a fixed author and committer per role (`Factory <role>`), `Factory-Role` and `Factory-Item`, no global or system config and the encoding pinned (`i18n.commitEncoding=UTF-8`); the check reads that commit. The paths git's status in the sandbox sees changed outside the role's own (with `core.fsmonitor` and `core.untrackedCache` off, `--no-renames`, `--ignore-submodules=all`) are named in an `alert` in the session's log, once, at the stop that passes or the second, and never committed; the status is never trusted: a clean or process filter the clone's attributes name may run under it, inside the box, and its failure or an overflow past 4 MiB is an `alert` that it could not list them, never a refusal of the output (slice 28-5b-3a). Test's output is only the test files it added, by the installed patterns and absent from the head, with a snapshot only beside one, found by a walk of the clone in the sandbox (at most 20,000 entries, the root `.git` and every `node_modules` left out); its existing test files are compared with the head's by blob ids computed in the sandbox, and one changed or deleted blocks the stop; it ends incomplete when it added none (slice 28-5b-3b). The walk starts at the include patterns' fixed folders (`tests/` today) and never enters a folder the head holds as a gitlink; an added path the head has a file, folder or submodule at or above, one that differs from a head path only in letter case, and a gitlink folder the session wrote in each block the stop, naming it; the reader's entries go on stdin; a path the walk or the reader cannot open blocks it, naming the way out (slice 28-5c-1); so does a walk root that is a link or a file, and an extglob part is never read as a folder (slice 28-5c-2). The Integrator's stop fails closed until station 6 has a checker (slice 28-5b). The passing head is removed only when it exists, and a check that passes without reading the output, but Intake's, is the factory's error (slice 28-5b-3b). The passing head, `refs/factory/passed/<id>`, is removed before the output is read, and written when the check passes for a session whose start record names it (`hasPassed`), naming the events commit on the head it read: a commit of the factory's own, the role's factory author and trailers (`Factory-Item` only for an item's work), whose one parent is exactly that head, changing only the work's event log (`specs/<issue>-<slug>/events.jsonl`, Define's `.factory/define/events.jsonl` on `claude/define`), every line already there byte for byte and the session's log lines, each checked as an event, appended after them; with no line in the session's log it names that head itself. When the events commit cannot be made, no passing head is recorded and an `alert` in the session's log says why, by its cause (slice 28-5c-3b); a log at the head that is not a regular file (a link, the executable bit, a gitlink, a folder) blocks the first stop with that reason, so the forced turn can remove it, and the second ends with no passing head and the alert (slice 28-5c-4b). A session log that cannot take the full alert fails the stop with that error, after the passing head is written (slice 28-5c-4c). A line of the session's log that is not an event is replaced by a factory `alert` line naming it, a log missing or unreadable gets one, and past 4 MiB of the session's lines or 48 MiB for the whole log what does not fit is left out, whole lines only, with one line naming where it starts and its bytes; the passing head is kept. When the session's lines no longer fit, the factory's line "the event log is full; later sessions' events are left out" goes in once, never while the log already ends with it, passing the limit by that line alone, and each session whose events are left out gets an `alert` in its own log (slice 28-5c-4b). A path the session's commits add or change below a folder named `events.jsonl`, in any letter case, blocks the stop, naming it; past the deadline the events commit's failure blocks the first stop (slice 28-5c-4a). After one forced continuation (`stop_hook_active`) the check runs again and may still record a passing head, but the stop is never blocked; what kept it from passing, a factory failure included, is an `alert` in the session's log (slice 28-5b-2) | AC-063 |
| `PreCompact` | `factory hook pre-compact` | Log, call request_split path, instruct stop | AC-037 |

Every hook has a `timeout` (`HOOK_TIMEOUTS` in `src/install/settings.ts`, seconds): session-start 60, the gate and each guard 30, post-edit 120, log 30, stop 600, pre-compact 30, so a tool call's hooks and the tool itself, summed (Bash: 30 + 30 + 600 + 30 = 690 s), stay under the launcher's `SILENCE`, 720 s, whether Claude Code runs them in turn or together (slices 28-5c-1, 28-5c-2). The launcher compares each of a pin's hook entries with the installed factory's whole, every key of the hook entry plus its group's `matcher`, not the group's other keys, and refuses one that differs in any field, a timeout included, with the repin way out (slice 28-5c-2).

Every block writes a `blocked` Event with role, tool, and the rule that fired.

The session's record is malformed, and every hook reading it blocks, when a field is missing or
of the wrong type, a field an event takes from it fails the event schema's own check (`role`,
`item`, `station`, `role_version` and `model`, never a Fable model), or its station is not its
role's: each role works
at one station, Verify's Test, Reviewer and Security at 5 and the Coach at Operate's 8.

**Limits.** Hooks run as the same user, on the same machine, as everything the agent runs.
The path guard sees only the Write and Edit tools; an agent with Bash can write files through
`git apply`, `tee`, `sed -i` or a script, and the command guard cannot analyse every program.
So for roles with a shell, path rules are defence in depth. The enforcement that holds is on
the laptop: `factory merge` checks protected paths on every pull request, and signed records
and main's signed history decide what counts (data-model § Pull request merge checks).
